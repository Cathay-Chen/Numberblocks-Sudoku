# Numberblocks Sudoku 代码与注释规范

## 1. 编码规范

1. 动作类型必须使用 `src/game/actions.ts` 的常量与联合类型，禁止裸字符串。
2. 游戏阈值（如错误上限、历史上限）必须抽为常量，禁止魔法数字散落在逻辑中。
3. 业务状态变更必须优先处理边界态：`completed`、`failed`。
4. 组件 Props 必须精确类型化，禁止 `any`。
5. 视图组件只负责渲染与事件透传，规则判断集中在 hook 或纯函数中。

## 2. 注释规范

1. 注释说明“为什么”，不复述“做了什么”。
2. 仅在复杂逻辑、边界决策、性能权衡处添加注释。
3. 注释保持一句话，优先中文，必要时附英文术语。
4. 过期注释必须在同次改动中清理。

## 3. 测试规范

1. 每次改动至少覆盖 1 个新增或回归测试。
2. 规则函数优先单测，UI 行为做关键路径测试。
3. 提交前必须通过：`npx vitest run` 与 `npm run build`。

## 4. 提交规范

1. commit message 使用 `feat/fix/refactor/docs/test` 前缀。
2. 单次提交聚焦单一目标，避免“顺手改一堆”。
3. PR 描述需包含：问题、方案、验证命令、风险点。
